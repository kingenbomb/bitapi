TINYFISH × BIT-API

让 AI 助手
搜索、读取网页。

用一把 bit-api 密钥，把 TinyFish 的网页工具接到你正在使用的 AI 客户端。配置一次，之后直接用自然语言提问。

MCP 服务地址Streamable HTTP
https://ai.baipiao.co/mcp

使用本站 API 密钥鉴权，无需另行注册 TinyFish。

01

准备一把本站密钥

  1. 进入 控制台 → API 密钥，登录或注册 bit-api 账号。
  2. 点击「创建密钥」，建议命名为 TinyFish MCP；也可以使用已有的有效密钥。
  3. 复制完整密钥，将下方配置中的 YOUR_BITAPI_KEY 替换为它，保留前面的 Bearer 和空格。

请妥善保管配置中的密钥。不要把含真实密钥的配置提交到代码仓库，或贴进公开截图和对话。

02

选择你的客户端

展开对应说明，完成其中一种配置即可。已有配置文件时，只合并 tinyfish 这一项，保留原来的其他设置。

Codex 桌面端 / CLI / IDE

在用户目录下的 ~/.codex/config.toml 加入以下内容。Windows 默认位置是 %USERPROFILE%\.codex\config.toml；如果设置过 CODEX_HOME，使用该目录中的配置文件。

config.toml
[mcp_servers.tinyfish]
url = "https://ai.baipiao.co/mcp"
http_headers = { Authorization = "Bearer YOUR_BITAPI_KEY" }

保存后重启 Codex，在 MCP 工具列表中检查 tinyfish；CLI 也可以运行 codex mcp list 查看是否已添加。

如果希望通过环境变量提供密钥，可将 http_headers 一行改为 bearer_token_env_var = "BITAPI_MCP_KEY"，并在启动 Codex 前设置此变量。桌面端需要完全退出并重新打开，才能读取新的环境变量。Codex 官方说明 ↗

Claude Code 终端命令

在终端执行下面这条完整命令。--scope user 让此配置在你的不同项目中都可使用。

Terminal · 单行命令
claude mcp add --transport http --scope user tinyfish https://ai.baipiao.co/mcp --header "Authorization: Bearer YOUR_BITAPI_KEY"

重新打开 Claude Code，输入 /mcp 检查连接状态；也可以在终端运行 claude mcp list。看到 tinyfish 已连接后，再发送下方示例。

这是 Claude Code 的配置方式。Claude Code 官方说明 ↗

Cursor mcp.json

在用户目录下的 ~/.cursor/mcp.json 中加入配置。Windows 默认位置是 %USERPROFILE%\.cursor\mcp.json。

mcp.json
{
  "mcpServers": {
    "tinyfish": {
      "url": "https://ai.baipiao.co/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_BITAPI_KEY"
      }
    }
  }
}

保存后在 Cursor 的 MCP 设置中确认 tinyfish 已启用、工具已加载，再在 Agent 对话中使用。未刷新时重新打开 Cursor。

Cursor 官方说明 ↗

OpenCode opencode.json

将以下 mcp 配置合并到你的 opencode.json 或 opencode.jsonc。这里使用 type: "remote"，并关闭 OAuth，直接通过本站密钥连接。

opencode.json
{
  "mcp": {
    "tinyfish": {
      "type": "remote",
      "url": "https://ai.baipiao.co/mcp",
      "enabled": true,
      "oauth": false,
      "headers": {
        "Authorization": "Bearer YOUR_BITAPI_KEY"
      }
    }
  }
}

保存后重新打开 OpenCode，运行 opencode mcp list 查看状态，再在对话中指定使用 tinyfish 工具。

03

在对话里试一次

先确认客户端已加载 tinyfish 工具，再复制下面的话发送给 AI。客户端询问是否允许工具调用时，按需确认。

搜索公开网页

search

请使用 tinyfish 的 search 搜索 Python asyncio 官方文档，列出前 3 条结果的标题、链接和简短说明。

确认结果：看到真实搜索结果及来源链接。

读取指定网页

fetch_content

请使用 tinyfish 的 fetch_content 抓取 https://example.com，以 Markdown 读取正文，然后告诉我页面标题和主要内容。

确认结果：返回内容包含「Example Domain」。

只回复「可以帮你搜索」不代表工具已运行。展开客户端的工具调用记录，确认调用的是 tinyfish 下的 search 或 fetch_content，并且返回了内容。以上两条路径已于 2026 年 10 月 13 日通过本站线上端点实测。

还可以用来做什么？

日常可以先搜索资料，再抓取其中的网页，要求 AI 对比、提取要点并附来源。TinyFish 还提供 run_web_automation、create_browser_session、create_monitor 等工具；可用项和参数以客户端实际加载的列表为准，涉及外部网站操作时先确认目标和操作范围。这些进阶工具不在上述搜索、抓取实测范围内。

费用与使用限制

本站 MCP 费用
当前工具调用记录为免费用量，不扣 bit-api 余额。AI 模型的对话费用仍由你使用的客户端或模型服务另行计算。
请求频率
默认每位用户每分钟最多 60 次 MCP 请求，同一用户的多把密钥共用额度。初始化、读取工具列表等协议请求也计入，实际限制以服务返回提示为准。
查看用量
到 控制台 → 使用记录 查看调用；工具名如 search、fetch_content 会显示在模型字段中。调用记录本身不代表抓取成功，应以工具返回结果为准。
上游可用性
工具仍受 TinyFish 的配额及目标网站限制。自动化、远程浏览器和监控等功能会消耗上游服务额度，本站免费不代表上游无限量。

遇到问题时

401 / Unauthorized：密钥未通过验证

确认使用的是 bit-api「API 密钥」页复制的完整密钥，已替换 YOUR_BITAPI_KEY，且密钥仍有效。请求头必须保留 Authorization: Bearer ，不要使用登录密码或 TinyFish 官方密钥。

429：请求过于频繁

暂停调用约一分钟，减少并发或反复重连，再试一次。换同一账号下的另一把密钥不会增加每用户限额；如果提示来自上游，以其返回的配额说明为准。

502 / 503：上游暂时不可用

可能是上游连接失败或暂时没有可用额度。稍后重试；持续出现时，向管理员提供发生时间、工具名称和脱敏后的错误信息。

工具没有出现，或连接中断

确认地址以 /mcp 结尾、类型为 HTTP / Streamable HTTP，配置已保存且客户端已重启。MCP 应添加到客户端的工具设置中，不填入模型的 Base URL。重连后仍失败时，查看客户端日志中的 HTTP 状态码；代理或网络需要支持流式响应。

能连接，但网页抓取失败或结果为空

先运行上面的 example.com 示例。它成功而目标页失败时，可能是目标网站需要登录、禁止访问或有反爬限制。请检查 URL，或换一个公开可访问的页面；搜索能找到链接不代表每个网页都能抓取。
