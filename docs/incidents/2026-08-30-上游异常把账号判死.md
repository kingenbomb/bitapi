# 2026-08-30 上游一次抽风就把账号判死

## 现象

任何一次上游超时或 5xx 都会让账号永久离开号池。`dead` 之后账号既不被
`pick_active` 取号、也不再被 `scan_once` 验活、还是 `purge` 的默认清理目标 ——
一次上游抽风,号就没了,而且不可逆。

两条流式路径更糟:`err` 和 `result["err"]` 写进去从来没人读,异常被吞掉后
外层只看到「一个 token 都没吐」,照样判死。

## 根因

热路径上的失败处理只有一个出口 `mark_dead`。没有「这次不行」和「这个号废了」
的区分,所以两类完全不同的故障落到同一个终态。

## 修法

`core/pool.py` 新增 `classify_failure(exc)`,把上游异常分成 `terminal`(账号真废了)
与 `transient`(过会儿再试),由 `mark_failure` 落状态:transient → `cooldown`,
terminal → `exhausted` / `dead`。调用点是 server.py 的 `_sync`、`_stream_sse`、
`_stream`、`_generate`,加上 `get_valid_account` 里 refresh 失败那处。

判据是**判不准一律 transient**:错判 cooldown 下一轮巡检会纠正,错判 dead 不可逆。
`scan_once` 把 `cooldown` 纳入巡检范围,这是 cooldown 回到 active 的唯一路径。

## 防复发:哪个门禁守着它

`tests/test_pool_failure.py`。核心那条是
`MarkFailureTest.test_transient_lands_cooldown_even_when_caller_says_dead` ——
断言 transient 必须压过调用方传进来的 `dead=True`,因为事故里正是那个参数
把临时故障写成了终态。

对旧代码是红的:事故前的 `core/pool.py` 里没有 `classify_failure`,整个文件
收集期就 ImportError。往后如果有人把 `mark_failure` 改回一律 dead,断言会直接失败。

跑:`python -m pytest tests/test_pool_failure.py -q`

## 加新失败分支时

口径要和渠道适配器的 `_probe_file` 保持一致 —— 未知的不可用状态也落
cooldown。不要把 `scan_once` 的 cooldown 巡检去掉。
