# 2026-08-31 portal 前端资源被浏览器缓存,整页白屏

## 现象

加公告铃铛时,portal 打开后**整页空白** —— 不是某个区块渲染错,是什么都不显示。
console 里是 `annRead is not a function`。

## 根因

`portal.html`、`portal-app.js`、`static/portal-*.js` 都没有版本号也没有内容哈希。
浏览器按启发式缓存缓住了旧的 `portal-shared.js`,配上新的 `portal-app.js`,
新代码调到旧文件里还不存在的函数,Vue 的 setup 抛异常 —— 而 setup 抛异常的后果
是整个应用挂掉,不是局部降级。

触发条件很低:**一次改动同时碰 `portal-app.js` 和 `static/portal-*.js` 就会遇到。**

## 修法

`server.py` 的三个路由 `/portal`、`/portal-app.js`、`/static/{name}` 都显式加
`Cache-Control: no-cache`(仍走 etag,命中时是空的 304,所以并不多花带宽)。

## 防复发:哪个门禁守着它

`tests/test_portal.py::PortalAssetCacheTest::test_front_end_assets_send_no_cache`。

它 glob `static/portal-*.js` 而不是写死文件名 —— 事故本身就是跨文件版本错配,
所以明天新增的 `portal-*.js` 必须自动被盖住。glob 为空时断言失败而不是静默通过,
否则资源一改名门禁就白装了。

对旧代码是红的:事故前的 `server.py` 三个 handler 一个 `Cache-Control` 都不发,
5 个 subtest 全红(`/portal`、`/portal-app.js`、三个 `static/portal-*.js`)。

跑:`python -m pytest tests/test_portal.py -q -k AssetCache`

## 别做的事

不要为了「省流量」把这几个头去掉。真要做缓存,得先给资源加内容哈希、并让
`portal.html` 引用带哈希的路径,那是另一件事。

改完前端在浏览器里看到白屏,先查 console 有没有 `is not a function` ——
那是缓存错配,不是代码写错。
